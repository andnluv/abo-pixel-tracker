## v0.3.22 — 비활성 히트·러트 주기 표시 수정

- **베타 남성의 주기 표시 수정:** `cycle.enabled=false`인 인물은 저장된 내부 간격·전조·활성·회복 숫자가 남아 있어도 주기 화면에 표시하지 않습니다. 화면에는 `주기 없음 · 약물`, `히트·러트 주기: 없음`이 나타납니다.
- **상태 및 RP 일관성:** 상태 카드의 주기 태그는 `주기 없음`으로, RP 연속성 프롬프트는 `cycle=none (disabled)`로 표시합니다. 비활성 주기에 약물 사건으로 남은 강제 활성 기록이 있어도 히트·러트 활성 단계로 계산하지 않습니다.
- **기존 설정 보존:** 사용자 수동 지정으로 `러트/히트: 사용`을 켠 예외는 기존처럼 주기를 표시합니다. 베타 여성의 별도 월경 가능 여부, 알파·오메가의 기본 주기, 약물·부작용·내성 기록 및 NPC 검색 코드는 유지했습니다.
- 기존 채팅 저장 데이터, 연결 프로필 및 토큰 값은 변경하지 않습니다. 서버 내 모바일 통합 테스트는 별도로 필요합니다.

## v0.3.21 — 월드 인포 NPC 2단계 검색

- **1차 · NPC 찾기**: `<인물>`, `[NPC]`, 개별 인물 프로필, `Name:`/`이름:` 필드, 제목과 성격·외모가 함께 있는 항목 및 팀/그룹 내 여러 인물의 목록을 찾아 후보를 제안합니다. 인물 설정집 원본은 변경하지 않습니다.

- **범위/한계:** 유효한 출처를 가져오지 못한 월드 인포는 AI에서도 탐색할 수 없습니다. 형식이 완전히 자유로운 글에서는 일부 미분류 항목이 보조 분석 대상으로 잡히지 않거나 AI가 근거를 반환하지 않을 수 있으므로, 누락이 0이라고 보장하지 않습니다.

## v0.3.11 — 개발 노트 반영: 임신 토글·약물·개별 취향

이 버전은 **SillyTavern 확장 소스** 변경입니다. 소개 게시글 HTML 수정본이 아닙니다.

- **임신 ON/OFF (채팅별 설정)**: `설정 → 임신 시뮬레이션 ON/OFF`. OFF 상태에서는 임신 노출 확률, 신규 임신 확정, 임신 진행·RP 주입을 수행하지 않습니다. **채팅 기록의 사건 자체는 삭제하지 않습니다.** 재활성화하면 사건을 다시 재생하므로 이전 임신 사건도 설정에 따라 재계산됩니다. 중요한 채팅은 먼저 내보내세요. 기본값은 ON이며 기존 채팅 데이터 키를 유지합니다.
- **약물·피임**: 기존 임신 가능성 4구간 확률과 응급 피임(72시간 내 기본 위험 감소 75%)을 유지합니다. 일반 피임약 이벤트를 추가하여 **확인된 정상 복용**의 가상 유효 시간(24h) 내에 임신 위험을 줄입니다(기본 감소 85%, 설정 가능). 응급 피임 감률·장기 억제제의 가상 배란 억제 성공률(기본 90%)도 채팅 설정에서 조절할 수 있습니다. 이미 판정된 임신을 응급 피임으로 소급 취소하지 않습니다.
- **부작용과 내성 분리**: 기존 약물별 부작용 발생 확률은 유지합니다. 부작용 발생 시 약 종류에 따른 구체적인 가상 증상 하나와 기록 시간을 별도 저장하며, `주기 → 약물 · 부작용 · 내성`에서 확인합니다. 부작용 확률 배율은 설정에서 조절할 수 있습니다. 정상 복용에 따른 내성 증가는 +0, 오남용 +6~10, 비승인 사용 +7~14 규칙을 보존합니다. 자동 분석이 꺼진 경우에는 같은 화면에서 복용 사실을 수동으로 기록할 수 있습니다.
- **개별 취향과 RP**: 기존 CHAR/USER의 명시적 확정 취향, 미확정 제안, 최근 장면 기록을 연결 상태 프롬프트에 추가하여 캐릭터별 차이를 반영하도록 했습니다. 미확정 취향을 확정·동의·필수 행동으로 취급하지 않으며, USER 대사와 행동을 모델이 임의로 결정하지 않도록 기존 원칙을 유지합니다.

## 초기 셋업

1. `확장(마술봉) → 그날의 사정` → 왼쪽 `SETUP`을 엽니다.
2. `CHAR + USER 분석 제안 만들기`를 클릭합니다. 현재 연결/선택한 저장 프로필의 분석 API가 **1회 호출**됩니다(비용 발생 가능).
3. 캐릭터 카드·페르소나로부터 성별, 제2성별, 신체 유형, 생식 능력, 생리·페로몬·언어·접촉 성향, 확정 취향 및 **잠재 취향 3~5개**와 별도의 확정 취향을 제안합니다. 분석 모델이 근거를 바탕으로 제안하고, 선택·해제는 사용자가 결정합니다.
4. `CARD FACT`는 카드·페르소나에 명시된 내용, `SUGGESTION`은 모델 추정입니다. 추론한 제안은 기본 미선택이므로 적용할 항목을 체크하고, 필요하면 값을 수정할 수 있습니다. 수동 변경으로 이미 고정된 항목은 자동 제안으로 덮어쓰지 않습니다.
5. `✓ 선택한 제안 적용`을 누르면 체크된 제안만 실제 채팅별 상태에 반영합니다. **분석 제안 생성만으로 상태가 바뀌지 않습니다.**
6. `제안 버리기`로 미적용 분석 초안을 폐기하거나 `다시 분석`을 누를 수 있습니다.

## v0.3.5 — 초기 프로필 분석 결과 한국어 출력

- 초기 CHAR·USER 프로필 분석 모델에 **한국어 응답 규칙**을 추가했습니다. 페로몬·접촉·발성·언어 성향의 서술값, 제안 근거(reason), 취향 후보 표시명(label)을 자연스러운 한국어로 요청합니다. 모델이 규칙을 지키지 않는 경우는 있을 수 있으며, 응답을 재번역하는 별도 API는 호출하지 않습니다.
- 취향 후보는 **영문 snake_case 내부 ID + 모델이 생성한 한국어 표시명**을 함께 반환할 수 있습니다. `name_binding`처럼 미리 등록되지 않은 ID도 번역 사전으로 임의 번역하지 않습니다. 모델이 생성한 한국어 명칭을 화면에 보여주며, 선택 적용 이후에도 해당 표시명을 보존합니다. 취향 ID와 저장 엔진의 판정 방식은 변경하지 않았습니다.
- 모델의 프롬프트에 NSFW/BDSM·친밀 관계·발성·ABO 기본 용어를 **참고용 어휘**로만 포함했습니다. 제공된 예시를 일대일 강제 번역하거나, 예시에 든 취향을 자동으로 사실·선호로 판정하지 않습니다. 기존 한국어 정적 표시 사전은 이전 버전 데이터의 표시 호환성을 위해 유지합니다.
- 화면 문구를 **`잠재 후보 3~5개 · 확정 후보 별도`**, **`선택을 돕기 위해 제공되는 일반 후보입니다. 체크 시에만 적용됩니다.`**로 변경했습니다.
- `CONFIRMED`·`SUGGESTED`·`OPTIONAL`의 생성·선택 정책, 후보 개수, 수동 설정 보호, USER 페르소나 분리, 분석 연결, RP 사건 판독의 원문 인용 근거 검증은 변경하지 않았습니다. 이벤트 분석기의 `evidence`는 텍스트 대조를 위해 원문 그대로 유지됩니다.
- GitHub 업데이트 시 최상위의 `profile.mjs`, `preference-labels.mjs`, `index.js`, `manifest.json`, `package.json` 파일을 반드시 교체하세요. 월드 인포를 재설치할 필요는 없습니다.
